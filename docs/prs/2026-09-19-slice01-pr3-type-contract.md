# PR: Type contract pipeline (slice 01 PR 3)

Ticket: IAN-126 (slice IAN-123). Branch: `feat/slice01-type-contract`. Spec: `docs/superpowers/specs/2026-09-19-template-fastapi-nuxt-design.md`, criterion B-4 and the "Type flow" section. Plan: `docs/slices/slice-01-walking-skeleton.md`, PR 3.

## Summary

This PR connects the backend's Pydantic schemas to the frontend's TypeScript types before the first real endpoint lands in slice 02. FastAPI's OpenAPI document is exported to a committed YAML file, openapi-typescript turns that file into the committed `@repo/api-types` package, and the Nuxt app gets one openapi-fetch client typed by those types. A drift check regenerates both files and fails when either no longer matches the code, so the backend, the document, and the frontend cannot silently drift apart.

## What changed

- **`app/schemas/health.py`:** Pydantic models `HealthLiveness` and `HealthReadiness`, which the two health routes now declare as their response models. The response bodies are unchanged. The document now describes both bodies, so it has real schemas for the generated types and the drift test to work with.
- **`app/export_openapi.py`:** builds the app through `create_app()` and writes `apps/server/docs/openapi.yaml` (run as `uv run python -m app.export_openapi [--output PATH]`). Keys are sorted at every level, there are no timestamps, lines end in LF, and the title is always the default app name rather than `APP_NAME` from the environment, so an unchanged API exports byte-identical YAML on any machine. Building the document never connects to Postgres, so a placeholder URL with no credentials stands in when `DATABASE_URL` is unset.
- **`packages/api-types`:** a workspace package whose `generate` script runs openapi-typescript over the YAML into `src/schema.ts`, re-exported as `paths` and `components`. The generated file is committed and excluded from Prettier, so its bytes are exactly what the generator writes.
- **`apps/client/web/app/api/apiClient.ts`:** `createApiClient({ baseUrl, headers })` returns an openapi-fetch client typed by `paths`. A call to a path the document does not define fails `vue-tsc`.
- **`scripts/check-contract-drift.sh`:** regenerates both files into a temporary directory, prints a unified diff naming each committed file that differs, and exits 1 on any difference. It exits 2 when uv or openapi-typescript is missing, so a broken runner is never reported as drift, and it never writes into the tree (`uv run --frozen` neither re-locks nor syncs). The root `package.json` runs it as `pnpm check:contract`, and `.gitattributes` keeps both generated files LF.
- **Dependencies (R-331):** PyYAML, which was already installed through uvicorn but is now imported directly, plus `types-pyyaml` for mypy. openapi-typescript and openapi-fetch are both named in the spec's dependency list.
- **Spec and plan:** the spec's "Request path" section now describes header forwarding and a `/api` proxy that strips only the prefix, its R-331 list names PyYAML and `types-pyyaml`, and the slice plan records the scope change.
- **Product docs:** the feature list marks the shipped health checks as Partial until their e2e specs run, and adds a row for the type contract.

## Architectural decisions

- **The client takes headers rather than `useRequestFetch()`.** The spec's "Request path" section says the client passes `useRequestFetch()` as its fetch function. openapi-fetch needs a fetch that returns a standard `Response`, but Nuxt's `useRequestFetch()` returns an ofetch `$fetch` that resolves to parsed data, so the two do not fit without an adapter. The client therefore takes a base URL and the headers to forward. The `useApiClient()` composable that slice 03 adds with its first server-rendered call passes `useRequestHeaders(['cookie'])`, which forwards the incoming cookie the same way. The spec's "Request path" section is amended in this PR to match.
- **The health routes gained response models in this PR.** Without them the document described both bodies as a free-form string map, so the generated types would have been `Record<string, string>`, and B-4's test ("add a field to a response schema") would have had no schema to change. The response bodies are unchanged, and PR 1's tests still assert them.
- **The generated YAML is sorted and the generated TypeScript is left unformatted.** Both choices make regeneration byte-stable, which is what the drift check compares. The alternative, formatting the generated files, would make the check depend on the formatter's version as well as the generator's.
- **The drift check diffs fresh copies against the committed files instead of regenerating in place.** Regenerating in place and running `git diff` would leave the tree modified after a failed check, and the check would stop working in a checkout without `.git`.
- **The client tests run in Vitest's node environment.** Under the Nuxt environment, `@nuxt/test-utils` copies happy-dom's `fetch` and `Request` onto the global scope but leaves Node's `Headers`, and happy-dom's `Request` silently drops headers given as a Node `Headers` object, which openapi-fetch builds. happy-dom also strips `Cookie` as a forbidden header. The client is framework-free and runs in Node during server-side rendering, so a per-file `// @vitest-environment node` tests it in the realm it ships in. An earlier version of this branch patched the global `Headers` in a Vitest setup file instead; the review preferred the narrower fix.

## Reflection

The branch was cut at 17:19 local, the first draft of this document was written at about 17:40, and the review fixes landed at about 18:10. I first expected the header test to be a bug in how the client passed headers to openapi-fetch. Printing the request inside the client showed the header was already gone when openapi-fetch built the request, which pointed at the test environment rather than the client. A second probe found the cause: Node's `Headers` paired with happy-dom's `Request`. The test author had also caught a related trap in advance: happy-dom drops `Cookie` as a forbidden header, which is why the header test uses `X-Request-Id`. My first fix for the header problem patched a global in every Nuxt test, and the review's narrower fix, running the one framework-free test in the node environment, is the better one: it tests the client in the realm it ships in and does not change the environment other tests see.
